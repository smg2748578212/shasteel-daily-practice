# 手机后台与网站管理页

`management/` 提供人员、执行计划、任务队列和历史记录 API；`frontend/` 是同源的管理员页面。管理页复用已有站点的 `/assets/site.css`、`/assets/site.js` 和管理员登录会话。它不是独立登录系统。

## 部署结构

```text
浏览器 → 公网 Nginx → SSH 反向隧道 → 手机 127.0.0.1:5011
                                             ├─ 管理 API
                                             ├─ 单进程调度器
                                             └─ Chromium / 每人独立会话
```

在 Debian/Termux proot 的独立虚拟环境安装：

```bash
python3 -m venv /opt/daily-practice-venv
/opt/daily-practice-venv/bin/pip install -r requirements-management.txt
apt-get install --no-install-recommends chromium tesseract-ocr tesseract-ocr-chi-sim
```

ARM64 可以使用系统 Chromium，并设置 `DAILY_PRACTICE_BROWSER_EXECUTABLE=/usr/bin/chromium`，不必下载 x86 浏览器。

管理服务通过 `management/start.py` 读取 `DAILY_MANAGER_CONFIG` 指定的 JSON 文件，默认 `/var/lib/daily-practice/runtime.json`。该文件是字符串映射，除 `.env.example` 中的应用及模型设置外，需要：

| 参数 | 说明 |
| --- | --- |
| `DATABASE_URL` | 现有站点会话数据库，只用于验证站点用户与权限 |
| `SITE_SHARED_ROOT` | 现有站点 `shared/` 包的父目录，默认 `/opt/webapp` |
| `SHASTEEL_COMPLETION_API_URL` | 门户当日完成状态接口 |
| `SHASTEEL_SESSION_API_URL` | 门户查询令牌交换接口，不含用户名等查询参数 |
| `DAILY_MANAGER_DATA` | 受保护的运行数据目录 |
| `DAILY_MANAGER_PORT` | 回环监听端口，默认 `5011` |
| `DAILY_MANAGER_PUBLIC_URL` | 公开网站 HTTPS 地址，用于 QQ 汇总中的完整名单链接 |
| `DAILY_MANAGER_PAUSED` | 迁移时设为 `1`，仅允许手动检查，暂不扫描每日计划 |

使用一个 Gunicorn worker、四个 HTTP 线程。调度器还持有文件锁，避免多个进程重复执行。应通过 runit 或其他服务管理器运行 `management/start.py`，包括停机时的子进程清理。

将 `frontend/daily-practice.html` 和两个资源文件部署到站点根目录及 `assets/`，登记页面 ID `daily-practice`，设为仅管理员可见。管理 API 还会独立检查管理员角色，前端隐藏入口不能替代后端权限验证。

公网 Nginx 将 `/api/daily-practice/` 原样转发到专用隧道的回环端口，并透传 `Host`、Cookie、Authorization 和 `X-Forwarded-Proto`。API 限制请求体大小，修改接口拒绝跨站请求。

## 运行语义

- 每人配置姓名、工号、班组、门户密码、任务模式、每日时间和执行星期，时间统一使用 `Asia/Shanghai`。
- “仅查看进度”（`execution_mode=check`）：新增人员的默认模式，定时任务和默认手动任务只查询当日完成状态；已完成也会按计划刷新。前端禁用答题按钮，API 拒绝该人员的答题请求。
- “完成每日一练”（`execution_mode=run`）：定时任务先查询完成状态，未完成才自动答题。数据库升级时已有人员保留此模式，历史记录不变。
- 切换为仅查看进度时，尚未开始的答题任务会改为状态查询；已有答题任务运行中则拒绝切换，需结束后重试。领取任务时还会重新核对配置，防止旧队列提交答案。
- 全局串行执行；同一个人不能同时排队和运行多个任务。每人每天最多自动创建一次计划任务，可手动重试。
- 服务当天重启后，会补排已经到点且尚未创建的计划；完成每日一练模式会跳过已核实完成的人员。
- 暂停人员会取消尚未开始的排队任务，不中断已开始的任务。
- “检查状态”只查询门户完成标志，不生成题目、不提交答案、不发送通知。
- “完成每日一练”先检查是否已完成；未完成才答题，结束后再次调用门户接口验证。页面结果和脚本退出码均不能单独证明已完成。
- 失败、超时、异常重启和没有题目均不会写为完成。浏览器子进程最多运行 20 分钟。
- 移除人员会清除其已保存密码，并保留历史记录。原工号不会分配给其他人员。

## 数据与迁移

密码以 Fernet 加密后保存到 `manager.sqlite3`，API 仅返回 `password_set`。密钥文件 `credentials.key` 和运行配置均需权限 `0600`，数据目录需 `0700`。备份应同时保存数据库、密钥和运行配置，均不得提交 Git。

每人浏览器会话、令牌、截图和本地日志在运行数据目录下隔离。实际人员、门户地址、应用标识、题库、通知密钥和运行数据均不随源码分发。

切换顺序：备份旧计划；复制必要的私有配置和会话；在手机上完成离线测试、浏览器启动、两个只读状态检查；验证新 API 与网站权限；停用旧定时任务；启用手机调度。旧机器保留备份以便回退，不能让两个调度器同时运行。

## 无需网站登录的自助接入

`/daily-practice-public.html` 仅提供“用户、密码”两个输入框，不加载要求网站登录的 `site.js`，沿用站点公共样式。部署此页面及 `daily-practice-public.css`、`daily-practice-public.js` 即可，不应为该页面添加网站登录拦截。

公开接口：`POST /api/daily-practice/public/enroll`，JSON 仅允许两个字段：

```json
{"user":"00000002","password":"your-portal-password"}
```

接口先验证门户账号与密码，再将账号接入同一管理数据库，固定 `enrollment_source=public`、`execution_mode=check`、每天 `16:00`、执行星期全部七天、启用。前端传入的模式或时间字段会被拒绝。返回仅包含固定模式、时间、时区及下次查询时间，不返回工号、密码、其他人员或历史。

同工号重复提交不会新增人员；验证通过后更新密码并启用，从门户获取姓名，并保留管理员维护的姓名、班组及历史。原来由管理员配置的账号也会转为该入口的仅查询计划，排队中的答题改为查询；答题运行中或账号已移除时拒绝接入。首次在 16:00 之后接入的账号，从次日 16:00 开始；每人每天最多自动查询一次，失败不会自动重复创建当天计划。

管理员可维护自助人员的姓名、班组、密码及启停状态，不能通过管理接口将其改为答题模式或其他执行时间。查询结果和历史仍由管理员在原管理页查看，公开入口只用于接入和更新密码。

门户验证最多同时处理两次；同账号每 15 分钟最多提交 5 次，同来源最多 60 次，全局最多 300 次，超过返回 `429` 与 `Retry-After`。限制保存在单 worker 内存中，服务重启会清空。生产入口需要 HTTPS；现有同源限制、请求体限制、加密存储及管理接口权限继续生效。

## QQ 每日汇总提醒

网站管理服务由调度器在每天北京时间 16:00 之后、当批排队和执行任务全部结束时，向原有 `ASTROBOT_TARGETS` 发送一条汇总，不再由每个答题子进程分别发送。已完成只显示人数；未完成列姓名；查询失败和尚未查询单独列出，不当作未完成。统计范围为后台当前启用的人员，完成状态必须来自当天门户确认。

`daily_reports` 持久记录每天发送状态。服务重启不会重复发送，发送失败或结果不确定也不自动重发，避免网络超时造成重复提醒；失败记录保留以供排查。首次启用时已过 16:00，从次日开始，不补发当天旧消息。晨间自动完成结果并入当天 16:00 的汇总；手动单人检查不另发 QQ。脱机 CLI `run.py` 仍独立运行，不应同时启用旧服务器的定时任务。

消息格式示例：

```text
每日一练进度汇总 · YYYY-MM-DD
查询计划：北京时间 16:00
统计人数：12 人
已完成：9 人
未完成：2 人（示例甲、示例乙）
查询失败：1 人（示例丙）
尚未查询：0 人
```

## 全部名单页面与接口

公开只读页面 `/daily-practice-roster.html` 和接口 `GET /api/daily-practice/public/roster` 展示全部未移除人员，包括已暂停人员；每人仅返回姓名、班组、完成状态及最近查询时间。接口不返回工号字段、密码、内部人员 ID、任务日志或登录令牌。管理接口仍要求管理员身份。刷新页面只读本地查询记录，不访问门户，不发 QQ。

无日期参数时展示今日实时记录。通知中追加 `${DAILY_MANAGER_PUBLIC_URL}/daily-practice-roster.html?date=YYYY-MM-DD`，其页面使用 `GET /api/daily-practice/public/roster?date=YYYY-MM-DD` 获取通知生成时的持久快照，包含已完成的全部姓名。快照与发送记录在同一事务保存，之后新增、暂停、改名或移除人员不会改变旧通知名单。

通知计数仍只统计启用人员，页面单列暂停人数；正在查询、失败、未查询均明确标记。今日尚未生成通知快照时，带今日日期的链接展示实时名单；过去日期没有快照则返回 `404`，不拼凑历史名单。未来日期和非法参数返回 `400`。新字段 `daily_reports.roster_json` 自动迁移，原发送状态保持不变，不会补发或重复发送旧通知。

## 无浏览器的进度查询

`management/http_client.py` 使用三个 HTTP POST 完成查询：门户登录验证账号密码及返回身份；向配置的会话接口传入 `userName`、`appId` 获取查询令牌；携带 `Authorization` 查询当日完成状态。会话接口和应用标识仍从受保护运行配置读取，仓库不包含生产地址和标识。首次查询验证门户凭据，成功获取的令牌以 `0600` 权限缓存在每人的私有数据目录 `http_session.json`。后续查询直接携带本人的缓存令牌，通常只需一次完成状态请求。缓存绑定工号、门户接口配置及加密密码的版本指纹；修改密码会使旧缓存失效，不复用其他人员的登录状态。令牌的 `exp` 只用于提前判断缓存到期，真实性仍由门户验证；临近到期（提前 60 秒）或收到明确的 401/403 拒绝时刷新一次。网络超时和服务器故障不会清除原有令牌；连接建立超时最多重试一次，不因此重新登录；没有可读 `exp` 的令牌最多缓存 24 小时。

`check` 模式不会导入或启动 Playwright、Chromium、答题器、OCR 或模型服务。HTTP 失败、身份不符、令牌拒绝和非布尔完成值都会报失败，不会自动转为答题。`run` 模式在会话接口已配置时先执行 HTTP 检查，已完成直接返回，未完成继续使用原浏览器答题并按门户结果复核。每日 16:00 计划、QQ 批量汇总、完整名单及通知快照语义不变。

浏览器前端的题目生成和答案提交接口也已定位；本次仅将已实测的查询链路改为 HTTP，未用未验证的提交格式替代现有答题流程。
